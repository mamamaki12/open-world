# オフラインキャッシュ更新で旧版HTMLを残さない

- ブランチ: `codex/offline-update-cache`（mamamaki12/open-world）
- 依頼: 共有ワールドのUI総点検と、新規入室の切替修正を確実に公開版へ反映する。

## 方針
- PR #93公開後の「最新版にする」で古いindex.htmlが残ることを確認。長期HTTPキャッシュを付けたローカルの2版SWでも、更新後に旧HTMLが残る現象を再現した。
- `vite.config.ts`生成SWのプリキャッシュを`Request(..., {cache: 'reload'})`で取得し、古いHTTPキャッシュを再利用しない。ゲームのIndexedDB・セーブは保持する。
- 実際に生成した`dist/sw.js`を使い、旧HTTPキャッシュ→更新→新版HTML→オフライン再起動と、個人セーブ保持をブラウザで検証する。

## 進捗
- 済: 公開版の更新で旧アセットが残ること、ローカルSW更新でもversion1が残ることを再現。
- 次: 生成SWを使った回帰検査を追加し、HTTPキャッシュを再利用しない修正を実装・検証する。

- 済: 実際の生成SWを使った回帰テストで旧版はHTML更新失敗を確認。修正後はHTML更新を確認し、セーブ比較は保存時刻だけを除外する。
- 済: `cache: reload`で全プリキャッシュを取得する最小修正、CI world-sessionへ回帰テストを追加。型チェックとproduction build成功。
- 課題: ローカル実行ホストが切断したため、保存保持とオフラインまでの最終確認はCIで実行する。
- 次: CI全5ジョブ成功後にマージ・Pages公開を確認。EC2中継の更新待ちは`shared-session-takeover.md`参照。

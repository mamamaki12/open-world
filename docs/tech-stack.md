# 技術構成

> ゲーム設計書（[game-design.md](./game-design.md)）をもとに、しんごさんと決めた技術構成と最小プロトタイプの範囲です（2026-10-15）。

## 1. 決定事項

| 項目 | 決定 | 理由 |
|---|---|---|
| 言語 | TypeScript | 型があるので、パーツやお金の計算が増えても壊れにくい |
| 3D描画 | Three.js（React Three Fiber 経由） | Webで最も使われている3Dライブラリ。軽く、ブラウザですぐ遊べる |
| 画面・メニュー | React | ショップ、バイト、競馬・ボートレースなど、メニューの多い画面を作りやすい |
| 3Dの補助 | @react-three/drei | カメラ操作（視点の回転・ズーム）などの定番部品 |
| 状態管理 | Zustand | 所持金・配置パーツなどのゲーム状態を、3D側とメニュー側で共有しやすい |
| ビルド | Vite | 起動と更新が速い |
| セーブ（当面） | ブラウザ内保存（IndexedDB / localStorage） | サーバー不要で一人用の核を早く作れる |
| サーバー（後の段階） | 家の売買を入れる段階で追加 | 売買・相場・不正対策にはサーバー側での計算と保存が必要 |

比較して見送った案：
- **Babylon.js**：ゲーム向け機能はそろっているが、メニュー画面づくりに手間がかかる。
- **Unity（Web書き出し）**：読み込みが重く、ブラウザで手軽に遊ぶ体験から遠ざかる。

## 2. 段階的な導入

1. **一人用の核**：家づくり → お金（バイト・ギャンブル・建築費・売却・維持費・税金・家賃）。セーブはブラウザ内。
2. **サーバー追加**：アカウント、クラウドセーブ、相場の計算をサーバーへ移す。
3. **プレイヤー間の売買**：家の出品・購入。お金の増減はすべてサーバーで検証し、改造による不正を防ぐ。

サーバーの具体的な技術（ホスティング、データベース）は段階2の前に決める。

## 3. 家づくりの目標水準

しんごさんの指示（2026-10-15）：**パーツごとに選んで組み立てる方式で、ハウスメーカーの注文住宅（積水ハウスのような家）も建てられる本格的なものにする。**

最終的に目指すこと：
- **構造**：複数階（2〜3階＋吹き抜け）、階段、バルコニー、ベランダ、ポーチ、ガレージ
- **屋根**：切妻・寄棟・片流れ・陸屋根などの形、勾配、軒の出、屋根材
- **外装**：外壁材（サイディング、タイル、塗り壁、木など）と色、窓・ドアの種類とサイズ、サッシの色、雨どい、外構（塀、門、駐車場、庭）
- **内装**：床材・壁紙・天井、建具、キッチン・風呂・トイレなどの住宅設備のグレード
- **パーツごとの選択**：置いたパーツを選び、種類・素材・色・サイズを個別に変えられる
- **見た目の質**：光と影、素材の質感がわかる描画（PBRマテリアル、影、環境光）

技術への影響：
- パーツは「種類＋素材＋色＋寸法」のデータで表し、カタログ（JSON）に定義する。パーツや素材の追加はデータを足すだけでできるようにする。
- 壁・床・屋根は形を計算で作る（壁に窓の穴を開ける、屋根の形を間取りから作るなど）。
- マス目は1マス＝910mm（日本の住宅の基準寸法）を基本にし、細かい寸法は半マス単位で扱う。

## 4. 最小プロトタイプの範囲（家づくりだけ）

本格的な家づくりの土台を確かめるため、パーツ選択と多層の仕組みまで入れる。

### 入れるもの
- 土地1区画（910mmのマス目付き）を3Dで表示
- 視点の回転・ズーム・移動、階ごとの表示切り替え
- 床、壁、ドア、窓をマス目に吸着して配置（壁には窓・ドアの穴が開く）
- 2階建てと階段
- 屋根（切妻・寄棟・片流れ・陸屋根）
- パーツを選択して、種類・素材・色を変える（外壁材や窓の種類など数種ずつ）
- 家具（ベッド、ソファなど数種）を自由な位置・向きで配置
- 選択・削除、取り消し / やり直し
- 影と素材の質感が出る描画
- ブラウザ内へのセーブとロード

### 入れないもの（次以降）
- お金、建築費、着工と待ち時間
- 3階建て、吹き抜け、バルコニー、外構、住宅設備のグレード
- 部屋ツール、テンプレート
- バイト、ギャンブル、売却、相場
- サーバー、プレイヤー間の売買

### 完了の目安
ブラウザで開き、外壁と屋根を選んだ2階建ての家を建てて家具を置き、再読み込みしても家が残っていること。

## 5. コードの置き方（案）

```
src/
  world/      土地・グリッド・カメラ
  building/   パーツ定義、配置、吸着、壁・屋根の形の計算、取り消し
  catalog/    パーツと素材のカタログ（JSON）
  ui/         メニュー・ツールバー（React）
  state/      ゲーム状態（Zustand）
  save/       セーブとロード
```

ゲームのルール（配置の可否、将来の価格計算など）は描画から分けて書き、後でサーバーへ移しやすくする。
